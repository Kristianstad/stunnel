# stunnel
Secure and Minimal stunnel (TLS proxy). Runs as a non-privileged user and can therefore only listen on unprivileged ports (>=1024); map the port you want to expose with `-p`, f ex `-p 636:8636`.

A self-signed certificate is generated at startup if no private key is provided. The stunnel configuration is generated from the VAR-parameters below, or you can provide your own.

Logs go to stderr (`docker logs`). Increase VAR_DEBUG to log more.

## Environment variables
### pre-set runtime variables
* VAR_LINUX_USER="stunnel"
* VAR_LISTEN_PORT="8443" (the port this container listens to internally, must be >=1024)
* VAR_SERVICE="stunnel" (name of the stunnel service section)
* VAR_CLIENT="no" (set to yes to wrap a plain local listener in TLS towards a remote TLS server)
* VAR_DEBUG="5" (stunnel debug level, 0-7)
* VAR_DELAY="no"
* VAR_VERIFY_CHAIN="no"
* VAR_CA_FILE="/etc/ssl/certs/ca-certificates.crt"
* VAR_CONFIG_DIR="/etc/stunnel"
* VAR_CONFIG_FILE="/etc/stunnel/generated.conf"
* VAR_CERT_FILE="/etc/stunnel/stunnel.pem"
* VAR_KEY_FILE="/etc/stunnel/stunnel.key"
* VAR_CERT_CN="localhost" (common name of the generated self-signed certificate)
* VAR_CERT_DAYS="365" (validity of the generated self-signed certificate)
* VAR_FINAL_COMMAND='stunnel $VAR_CONFIG_FILE'

### Runtime variables
* VAR_HOST (host to connect to, required unless you provide your own configuration file)
* VAR_PORT (port to connect to, required unless you provide your own configuration file)
* VAR_VERIFY (stunnel verify level, 1-4. Optional)
* VAR_PROTOCOL (stunnel protocol negotiation, f ex pgsql. Optional)
* VAR_CIPHERS (stunnel ciphers. Optional)
* VAR_PSKSECRETS_FILE (file with PSK secrets. Optional)

## Certificate and private key
If VAR_KEY_FILE is missing or empty, a self-signed certificate and key are generated at startup (VAR_CERT_CN, VAR_CERT_DAYS). To use your own, mount them and point VAR_CERT_FILE and VAR_KEY_FILE at them. The files must be readable by the stunnel user (uid 102, gid 0).

The container refuses to start if only one of the certificate and the key is present.

## Your own stunnel configuration
If VAR_CONFIG_FILE exists and is not empty, it is used as it is and no configuration is generated (VAR_HOST and VAR_PORT are then not needed). The generated certificate and key are still created at VAR_CERT_FILE and VAR_KEY_FILE if missing, so your configuration can refer to them. Note that `setuid`, `setgid` and `chroot` must not be used, since stunnel never runs as root.

## Example
Secure an LDAP container named `directory` on port 636:

    docker run -d --name ldaps --link directory:ldap \
      --cap-drop ALL --cap-add CHOWN --cap-add SETPCAP --cap-add SETGID --cap-add SETUID \
      -e VAR_HOST=ldap -e VAR_PORT=389 -e VAR_LISTEN_PORT=8636 \
      -p 636:8636 \
      ghcr.io/kristianstad/stunnel

## Healthcheck
`healthcheck` (same program as in tcp_proxy) is included. Without arguments it connects to 127.0.0.1 on VAR_LISTEN_PORT. Use it without `--tls`: that option performs a PostgreSQL SSLRequest before the TLS handshake and is not meant for stunnel. Each check is a plain TCP connect, which stunnel logs as an "unexpected eof" error.

## Capabilities
Can drop all but CHOWN, SETPCAP, SETGID and SETUID.

## Differences from dweomer/stunnel
| dweomer/stunnel | This image |
| --- | --- |
| STUNNEL_SERVICE | VAR_SERVICE |
| STUNNEL_ACCEPT | VAR_LISTEN_PORT (port only, >=1024) |
| STUNNEL_CONNECT=host:port | VAR_HOST and VAR_PORT |
| STUNNEL_CLIENT | VAR_CLIENT |
| STUNNEL_DEBUG (default 7) | VAR_DEBUG (default 5) |
| STUNNEL_CAFILE | VAR_CA_FILE |
| STUNNEL_VERIFY_CHAIN | VAR_VERIFY_CHAIN |
| STUNNEL_KEY | VAR_KEY_FILE |
| STUNNEL_CRT | VAR_CERT_FILE |
| STUNNEL_DELAY | VAR_DELAY |
| STUNNEL_PROTOCOL | VAR_PROTOCOL |
| STUNNEL_VERIFY | VAR_VERIFY |

* Runs as a non-privileged user, without `setuid`/`setgid` in the configuration.
* Logs to stderr instead of /var/log/stunnel/stunnel.log.
* The CA file and certificate are no longer added to the system trust store at startup.
* No envsubst/gettext. The configuration is generated by a shell script (`finalfs/start/stage3/100-stunnel`).
* A pid file is not used.
